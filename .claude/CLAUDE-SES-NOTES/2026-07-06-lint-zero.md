## The store migration (the real change)

New primitives in `src/hooks/`: `storageStore.ts` (`createStorageStore` +
`useStorageStore`; getServerSnapshot = deterministic default, lazy cached
getSnapshot, `set()` persists + notifies) and `useHydrated.ts`.

Per-feature stores in each `storage.ts`: `todoStore`, `notesStore` (shared by
/notes and /notes/editor), `gpaStore`, `calendarStore`, and in
`dashboard/storage.ts` the shared `layoutStore`/`themeIdStore`/
`customThemesStore`/`builtInOverridesStore`/`deletedBuiltInIdsStore` (dashboard
+ settings now see the same live theme state). `useClock` became a module-level
time store. SettingsView's `settingsDisplay` got its own store.

Behavioral consequences (all deliberate):
- `set()` persists → all scattered `saveX(next)` calls next to `setState` were
  removed (toDo/notes/gpaCalc children); useCalendar's skip-first-save guard
  and gpaCalc's persist-on-change effect are gone.
- `load()` is read-only (it runs during render via getSnapshot) → the notes,
  toDo and calendar first-visit **seed writes moved out of load**; seeds persist
  on the first real mutation.
- Derived-with-override replaced effect-initialized state: gpaCalc `mode`
  (`override ?? (setupComplete ? "app" : "setup")`) and `activePeriodId`;
  calendar `year`/`month`/`weekStart` follow `today` until the user navigates.
- toDo visibility inverted to `hiddenListIds` (all-visible default, no
  post-load init). ListSidebar's create-list auto-toggle removed — under
  inverted semantics it would have HIDDEN the new list.
- settings `handleResetSettings` rewrites defaults through the stores instead
  of `localStorage.removeItem` (loads identically, keeps caches consistent).
